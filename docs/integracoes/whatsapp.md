# Integração — WhatsApp (recepção automatizada via Chatwoot)

Documento criado em 2026-09-03, na auditoria estratégica do Strategic Manager, para fechar uma lacuna de rastreabilidade: esta arquitetura já está em produção desde 2026-08-20 (Chatwoot) e foi revisada em 2026-09-02 (fluxo de boas-vindas com botões), mas não havia nenhum registro em `docs/` até esta entrada — só em memória de sessões anteriores e no código. Este arquivo documenta o estado real, não uma proposta.

## O que existe hoje

- **Chatwoot self-hosted** (Hetzner + Docker) é o inbox real do número de WhatsApp Business da Aurum Peptide desde 2026-08-20. É onde o atendimento humano hoje vê e responde as conversas.
- **Caminho de recepção real de mensagens:** o Chatwoot registra sua própria URL de callback direto na Meta para esse número de telefone, **sobrepondo** a configuração a nível de app que o webhook antigo do projeto usava. Descoberto em 2026-09-02.
  - `apps/site/app/api/chatwoot/webhook/route.ts` — webhook de **saída** do Chatwoot (evento `message_created`), autenticado por segredo compartilhado na própria URL (`CHATWOOT_OUTGOING_WEBHOOK_SECRET`), filtrado por `CHATWOOT_INBOX_ID`. **Este é o único caminho que recebe mensagens reais de clientes hoje.**
  - `apps/site/app/api/whatsapp/webhook/route.ts` — webhook oficial da Meta (Cloud API), configurado a nível de app. Só recebe tráfego de admins/testers do app — **sem uso real** enquanto o App Review de publicação não for aprovado pela Meta.
- **Automação de boas-vindas** (`apps/site/lib/whatsappAutomacao.ts`), compartilhada pelos dois pontos de entrada acima: na primeira mensagem de um contato novo, envia uma mensagem interativa com 2 botões ("Entrar no grupo" e "Falar com vendedor"). Ao clicar, o sistema responde com um botão CTA de URL (`cta_url`) apontando para o Grupo VIP (`https://chat.whatsapp.com/JqgzFxfecrnCnJLrBNyEhb...`) ou para o WhatsApp pessoal do vendedor (`https://wa.me/5515981890060`).
- **Histórico de revisões do texto**, pelo código: versão original sem CTA (18/08/2026) → revisão para incluir Grupo VIP + site + aviso de PDF (18/08/2026, `docs/marketing/conteudo.md`) → nova versão com botões nativos + banner, "aprovada pelo usuário em 2026-09-02" (comentário no código, sem entrada correspondente em `docs/marketing/conteudo.md`).

## Lacuna de rastreabilidade identificada nesta auditoria

O texto vivo em produção hoje (`MENSAGEM_GRUPO_VIP` em `apps/site/lib/whatsappAutomacao.ts`) diverge do registro em `docs/tom-de-voz.md` e `docs/valores.md` em pontos concretos — ver `docs/analytics/relatorios.md`/relatório desta auditoria (2026-09-03) para o detalhe e a recomendação. Este arquivo só documenta a arquitetura técnica; a revisão de tom da copy é uma pendência separada, sinalizada ao Strategic Manager/usuário, não decidida aqui.

## Message Template `convite_grupo_vip` (submetido 2026-09-03, aguardando revisão da Meta)

Motivação: usuário pediu a capacidade de disparar convite de WhatsApp para clientes já cadastrados que não escreveram recentemente (fora da janela de 24h da Cloud API) — isso exige um Message Template pré-aprovado pela Meta, diferente do fluxo de boas-vindas acima (que só responde dentro de uma sessão já aberta pelo cliente).

- **Nome:** `convite_grupo_vip` · **Categoria:** MARKETING · **Idioma:** `pt_BR` · **Template ID:** `1311186610929757` · **Status na submissão:** `PENDING` → **`APPROVED` (confirmado 2026-09-06 via API).**
- **Corpo:** mesmo texto/tom do `MENSAGEM_GRUPO_VIP` (lista de peptídeos em destaque, emojis, "condições especiais"), **suavizado especificamente para esta submissão** — removidas as 3 linhas de urgência/escassez ("PROMOÇÃO...COMEÇOU", "condições exclusivas por tempo limitado", "aproveite enquanto durarem os estoques") por decisão explícita do usuário, para reduzir risco de rejeição pela revisão automática da Meta (categoria Marketing é escaneada para esse padrão). **A mensagem `MENSAGEM_GRUPO_VIP` do fluxo de boas-vindas não foi alterada** — essa suavização vale só para este template.
- **Botões:** 2× `QUICK_REPLY` ("Entrar no grupo", "Falar com vendedor") — não `URL` direto, porque a API da Meta rejeita botão de template com link direto para `wa.me`/`chat.whatsapp.com` (`error_subcode 2388081`, testado nesta submissão). Ao contrário do fluxo de boas-vindas (que já trata esses mesmos botões via `processarCliqueBotao`), **o payload customizado dos botões (para casar com `BOTAO_ID_GRUPO`/`BOTAO_ID_VENDEDOR`) ainda não foi configurado** — isso se define no momento do envio real da mensagem (parâmetro `components` da chamada `POST /{phone-number-id}/messages`), não na criação do template. Pendência a resolver quando o disparo real for implementado.
- **Rodapé:** não pode ter emoji nem quebra de linha (`error_subcode 2388073`, descoberto nesta submissão) — usado só texto simples.
- **Submetido via:** chamada direta à Graph API (`POST /{whatsapp-business-account-id}/message_templates`), script de execução única (criado em scratchpad, apagado depois — mesmo padrão já usado pelo Publishing Manager para captions), sem alterar `scripts/meta_graph.py`.
